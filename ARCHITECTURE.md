# ATIP architecture and integration contracts

## Runtime topology
`apps/web` Next.js TS App Router UI; `services/api` FastAPI modular monolith (`identity`, `organizations`, `github`, `repositories`, `mining`, `risk`, `plans`, `runs`, `agents`, `reports`, `audit`); `workers/` dedicated miner, analysis, orchestrator, reporting and sandbox-dispatch workers; `packages/` versioned contracts and provider adapters; `infra/` Compose, Kubernetes, observability. PostgreSQL authoritative for jobs/approvals; Redis cache/ephemeral state; RabbitMQ durable messages, PostgreSQL transactional outbox, idempotent consumers; S3-compatible object store for large logs/artifacts. Never run user repo scripts in control/processing plane.

## Key entities
`organizations`, `users`, `memberships`, `github_installations`, `repositories`, `repository_snapshots`, `commits`, `file_changes`, `dependency_edges`, `analysis_runs`, `risk_assessments`, `test_cases`, `test_plans`, `test_runs`, `execution_jobs`, `agent_runs`, `agent_steps`, `artifacts`, `approvals`, `audit_events`, `outbox_events`. Every tenant-owned entity has `organization_id`; version and provenance are retained. Migrations via Alembic; typed schemas and API contracts.

## API v1 baseline
`GET /api/v1/me`, `GET /api/v1/organizations`, `GET /api/v1/repositories`, `GET /api/v1/repositories/{id}`, `POST /api/v1/repositories/{id}/sync`, `POST /api/v1/repositories/{id}/analyses`, `GET /api/v1/analyses/{id}`, `GET /api/v1/analyses/{id}/events` (SSE), `GET /api/v1/repositories/{id}/risks`, `GET /api/v1/test-plans`, `POST /api/v1/test-plans/{id}/approve`, `GET /api/v1/test-runs`, `GET /api/v1/test-runs/{id}`, `POST /api/v1/execution-jobs/{id}/cancel`, `GET /api/v1/reports`, `POST /api/v1/webhooks/github`, and auth/provider settings endpoints. Extend carefully with OpenAPI contracts. Mutation idempotency keys, pagination, typed error envelopes, tenant authorization, request IDs.

## Lifecycle
GitHub webhook → verify/dedup → immutable snapshot → mine diff/history/dependencies/coverage → score risk → propose tests → policy evaluation → queue authorized isolated execution → collect results → AI triage → report/check. Execution job `CREATED→QUEUED→PROVISIONING→RUNNING→COLLECTING→COMPLETED` with `FAILED/CANCELLED/TIMED_OUT` and retry transitions; agent approval waiting state is separate. All transitions persisted and recoverable.

## ML lifecycle and deployment contracts
- Keep deterministic risk scoring as the always-available baseline. Add optional versioned supervised model inference through an adapter; never make core risk API availability depend on a model artifact or external LLM.
- Construct permissioned training datasets from immutable commit snapshots, code-change features available at prediction time, and defensible defect-linked outcomes with provenance. Store dataset manifests, labeling policy, cutoff timestamps, schema/version, repository and time split membership; avoid future-information leakage, duplicate-commit leakage, and cross-tenant training without explicit consent.
- Reproducible CPU-friendly LightGBM/XGBoost baseline experiments first; training scripts with pinned dependencies/seeds, metrics and calibration, temporal + held-out repository evaluation, and comparison with deterministic heuristic. Insufficient trustworthy labels means training remains unvalidated, not a manufactured success.
- Store versioned model artifacts and evaluation reports in approved object storage; record training data/version, checksum, provenance, deployment status and rollback target. Load via isolated inference worker/service or risk module with resource limits and health checks; monitor latency, errors, drift and post-deployment quality. Promotion requires measured acceptance criteria and approval.
- LLM test generation/failure triage uses pretrained provider APIs with privacy consent, redaction, budgets and structured output validation; no from-scratch foundation-model training is required.

## Developer experience
Use `pnpm` for web and `uv` for Python; lock dependencies; Compose for local Postgres/Redis/RabbitMQ/object storage; explicit `.env.example` without real secrets; CI for lint/type/test/build/security. Add browser E2E tests with Playwright. Prefer contract tests and mock adapters for external services. Never claim external GitHub/AI/sandbox flows are verified without live authorized test.

## Reliability and targets
At-least-once delivery, idempotent consumers, DLQ and bounded retry, structured logs/traces/metrics, correlation IDs, backups and restore drills. Aspirational post-stabilization 99.9% availability, p95 <300ms for normal cached reads, RPO ≤24h, RTO ≤4h; **targets, not current claims**. Kubernetes/Argo CD production rollout only after hardened execution isolation and operational readiness.

## White-box testing architecture and proof contracts
**Pipeline:** GitHub repository → authorized branch/PR snapshot → repository mining (commits, diffs, dependencies, existing tests) → versioned explainable risk scoring (optional validated ML) → static white-box analysis (AST, CFG, call graph, data-flow/def-use, complexity, reachability) → coverage objective inventory (statement, decision/branch, condition, MC/DC, basis/selected feasible paths, loops, def-use, exceptions, boundaries, mutation, impacted regression) → constraint/fixture/LLM-assisted candidate test generation → validation and review → authorized hardened sandbox execution with instrumentation → measured coverage and mutation analysis → gap-driven regeneration and re-execution with bounded retries → evidence-grounded AI failure analysis → auditable dashboard/GitHub Checks and exports.

- Modules: `whitebox/parsers` (Python `ast` and JS/TS language-aware parser adapters), `whitebox/cfg`, `whitebox/dataflow`, `whitebox/objectives`, `whitebox/constraints`, `whitebox/generation`, `whitebox/instrumentation`, `whitebox/mutation`, `whitebox/regression`, `whitebox/coverage`, `whitebox/gaps`; test runners and LLM gateway remain separate. Prefer mature coverage/mutation tools where they can provide valid evidence; build a custom condition-level MC/DC tracer/validator where necessary and clearly scope language support.
- Entity additions: `whitebox_analyses`, `coverage_objectives` (stable ID, SHA, source span, kind, language, reachability status, required evidence), `test_objective_links`, `instrumentation_sessions`, `coverage_observations`, `mcdc_pairs`, `mutants`, `mutation_results`, `regression_selections`, `coverage_gaps`, `generation_attempts`, `tool_capabilities`. Tenant IDs and immutable run/source version on every record.
- New APIs: `POST /api/v1/repositories/{id}/whitebox-analyses`, `GET /api/v1/whitebox-analyses/{id}`, `GET /api/v1/whitebox-analyses/{id}/objectives`, `GET /api/v1/whitebox-analyses/{id}/coverage`, `GET /api/v1/whitebox-analyses/{id}/gaps`, `POST /api/v1/whitebox-analyses/{id}/generate-tests`, `POST /api/v1/whitebox-analyses/{id}/rerun-gaps`, `GET /api/v1/test-runs/{id}/mutation-results`, and tenant-scoped export. Use versioned OpenAPI and idempotent async jobs; generation/execution permissions enforced on server.
- Explicit objective status machine: `DISCOVERED → CANDIDATE → INSTRUMENTED → COVERED | UNCOVERED | PROVEN_INFEASIBLE | UNKNOWN | UNSUPPORTED`; statuses require evidence and versioned tool capability. `PROVEN_INFEASIBLE` requires recorded proof/constraint; solver timeout is UNKNOWN. Static discovery alone is never coverage.
- MC/DC proof record: decision source span and normalized expression, atomic condition IDs, instrumentation observations (true/false and short-circuit/unevaluated states), two actual executed tests, complete condition vectors and decision outcomes, independence method (`unique_cause`/`masking`), evidence and validator version. Short-circuit conditions not evaluated must not be fabricated.
- Basis-path and selected-path objectives must include CFG version, bounded feasibility result and covered edges; report theoretical vs feasible/attempted paths separately. Data-flow observations require def-use IDs and observed traces where available. Mutation uses reproducible isolated worker runs and separate denominator classifications.
- Coverage adapter capability matrix per Python/JS/TS and tool versions: native statement/branch support is not assumed to imply condition, MC/DC, data-flow or full path instrumentation. If unsupported, show explicit limitations and a failing acceptance gate for any mandatory claimed technique.
- Risk model predicts prioritization, not proof of a bug; LLM supplies candidate tests/explanations, not coverage truth. Only validated instrumentation and test outcomes produce coverage evidence.
- Safety: no arbitrary source/test execution in miner or API workers. Static parsing must be resource-bounded; generated tests and mutation runs execute only in hardened sandbox; no host Docker socket, platform secrets or default network; enforce tenant quotas and approved permissions.
